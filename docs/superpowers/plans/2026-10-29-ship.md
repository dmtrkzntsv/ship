# ship Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `ship`, a Go CLI that publishes built project files to R2 and installs/operates them as systemd services, plus its setup Action, installer, release workflow and Homebrew formula.

**Architecture:** Pure packages (`layout`, `sums`, `config`, `state`) hold names, rules and file formats. `store` abstracts R2 behind an interface with an in-memory fake. `release` does publish/prune/versions/fetch against a `store.Store`. `host` performs filesystem and systemd operations under a configurable root through a `Sys` interface (faked in tests). `app` orchestrates config + store + state + host for each command. `cli` is thin cobra wiring. An end-to-end script exercises the real binary against MinIO and real systemd on a GitHub runner.

**Tech Stack:** Go 1.26, `github.com/spf13/cobra`, `github.com/aws/aws-sdk-go-v2` (`service/s3`, `credentials`), `github.com/BurntSushi/toml`, stdlib `syscall.Flock`. MinIO for integration/e2e tests.

**Spec:** `docs/superpowers/specs/2026-10-24-ship-design.md` — read it before any task; this plan cites its rules rather than repeating them.

## Global Constraints

- Module path `github.com/dmtrkzntsv/ship`; the repo is renamed to `dmtrkzntsv/ship` right after merge, so all URLs, the Action (`dmtrkzntsv/ship@v1`) and the Homebrew homepage use the new name.
- `CGO_ENABLED=0`; release targets linux amd64/arm64/arm (GOARM=6), darwin amd64/arm64.
- Name regex for project, component and service: `^[a-z0-9][a-z0-9_-]*$`. Version regex `^[A-Za-z0-9._-]+$`, never `latest`/`dev`.
- Moving channels are exactly `latest` and `dev`; everything else is immutable.
- Cache-Control: immutable `public, max-age=31536000, immutable`; moving `no-cache`. Content-Type `application/octet-stream`.
- S3 client: region `auto`, path-style addressing, `RequestChecksumCalculation` and `ResponseChecksumValidation` = `WhenRequired`.
- Default bucket `lab`; default `--keep` 10; health check: unit stays active for 10 s, polled every 1 s; failure prints the last 30 journal lines.
- Host paths for service `S`, ref name `N`, asset `A`: `/opt/S/A` (+`.prev`), `/etc/S/N.env` (0640 root:S), `/var/lib/S` (0750 S:S), `/run/S` (0750 S:S via `/etc/tmpfiles.d/ship-S.conf`), `/etc/systemd/system/<unit>.service`, unit backup `/opt/S/<unit>.service.prev`.
- Placeholders exactly: `{{SERVICE}} {{USER}} {{BIN}} {{BIN_DIR}} {{ENV_FILE}} {{DATA_DIR}} {{RUN_DIR}} {{UNIT}}`; any other `{{…}}` is an error.
- Config `/etc/ship/config.toml` (root) or `~/.config/ship/config.toml` (non-root, checked first); env `SHIP_R2_ENDPOINT`, `SHIP_R2_ACCESS_KEY_ID`, `SHIP_R2_SECRET_ACCESS_KEY`, `SHIP_R2_BUCKET`, `SHIP_CF_API_TOKEN` override file values. State `/var/lib/ship/state.json` (0644), lock `/var/lib/ship/state.lock`, cache `/var/cache/ship/listing.json`.
- Host-changing commands require root; on non-Linux, host commands exit with `ship <cmd>: Linux only`.
- No secrets, hostnames, domains or zone ids anywhere in the repo (it is public); examples use `<account_id>`, `example.com`.
- Every package keeps tests next to code (`*_test.go`); `go test ./...` must pass without network; MinIO tests are skipped unless `SHIP_TEST_S3_ENDPOINT` is set.

## Review Focus

1. **An update that fails midway** (unit verification fails after the new binary is in place, or restart errors) must leave the old binary and unit in place and running — tested in Task 11 (`TestUpdateVerifyFailureRestoresBinary`).
2. **A moving channel republished while a host downloads** gives a checksum mismatch; nothing outside the temp dir may change — tested in Task 8 (`TestFetchMismatchLeavesNoFiles`) and Task 10 (`TestInstallFetchErrorTouchesNothing`).
3. **A read-only R2 key used for publish/prune** must fail with a message naming the cause, not a raw AccessDenied — tested in Task 6 (`TestPublishReadOnlyKeyMessage`).
4. **A unit file that already exists but is not in state** (script-installed service, hand-written unit) must never be overwritten by `install` — tested in Task 10 (`TestInstallRefusesForeignUnit`).
5. **Uninstalling the last ref without `--purge`, then reinstalling**: user and data survive, the reinstall reuses them and keeps the env file — tested in Task 12 (`TestUninstallLastKeepsDataAndUser`, `TestReinstallKeepsEnvFile`).
